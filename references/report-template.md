## 填写规则（给自己看，交付时删除本节）

**必须遵守**

1. **顺序即优先级**：概览 → 高风险未通过 → 中风险 → 低风险 → 全部 MUST → 待人工定级 → 本地实现 → SHOULD/MAY → 范围限制。
2. **每条"符合"都要有 E1 证据**（`文件 :: 函数 :: 片段`），否则改判"无法判定"。
3. **每条"不符合"要区分形态**：`违规实现` 或 `确认缺失 + 已检查位置`。
4. **每条"无法判定"要写卡点**：缺哪个文件 / 哪条调用链断 / 哪个判据歧义。
5. **证据用反引号包裹**，文件路径写仓库相对路径，行号只作辅助（可省略）。

**禁止**

| 禁止 | 原因 |
| --- | --- |
| 只写"已覆盖"、"未实现" | 无法复核，等于漏报 |
| 写"整体基本满足" | 合并判定会掩盖具体未通过项 |
| 写"建议后续补充" | 把"不符合"降级成建议 |
| 让明细表缺条目 | 漏一条 MUST 即报告无效 |
| 在报告里评价命名/分层/性能风格 | 越界，不属于覆盖检查 |
| 保留未填的 `〈占位符〉` 交付 | 说明检查没做完 |

**交付前自检**：`SKILL.md` 第 7 节的 10 项，逐项打勾。
